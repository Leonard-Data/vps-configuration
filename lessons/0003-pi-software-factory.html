A small software factory.

Give a coordinator one harmless job, watch its crew work, then reconnect without starting everything again.

Lesson 3 · 8-minute explanation · guided installation: allow 60–120 minutes, stopping at each checkpoint

You run the installation. This page changes nothing.

We use the MSP orchestration guide with extra VPS safety checkpoints. Your Ubuntu version, SSH access and available RAM are still unverified. This is a separate Pi setup, not a Hermes upgrade. You do not need to install Hermes first.

Recall before installing

Without reopening Lesson 2, say which SSH key stays on Windows and why you keep a working administrator session open. Then explain why a normal Linux account is safer than root—but still able to damage its own files.

Four roles. One small job.

Pi — the agent runtime
Connects a model to tools such as reading files and running shell commands. Pi alone is not a multi-agent factory. Pi quickstart
FirstMate — the coordinator workspace
Provides instructions, skills and extensions for planning and delegating work to a crew. Run Pi from this reviewed workspace. Guide and workspace link
Herdr — persistent terminal workspaces
Keeps coordinator and crew tabs on the server when you detach. It is not the agent’s brain and does not make a VPS reboot harmless. Herdr source
Treehouse — separate Git worktrees
Gives parallel work separate checkouts in one Git repository. Worktrees reduce file collisions; they do not isolate Linux permissions. Treehouse source

Think: you → FirstMate running in Pi → crew tabs in Herdr → worktrees managed by Treehouse. The guide also installs AXI command helpers. Current FirstMate additionally requires No Mistakes ≥1.46.0, even though its PR/CI workflow can wait; the playbook corrects the guide’s older optional-tool description.

Your real boundary is the operating system.

Run the factory as a dedicated account with no sudo, no production keys and no access to unrelated private data. A project directory, a worktree and “local-only” instructions are not a sandbox. Pi can execute tools without asking you about every call. Project trust is permission to load executable project resources—not a guarantee that they are safe. Pi security model

“Local-only” avoids remote delivery, but FirstMate can still perform an approved local landing. For this lesson we additionally request no local merges or deployment, and leave the result on its worktree branch. Neither setting blocks network access. GitHub and model credentials remain sensitive, and multiple crew agents can increase model charges. Start with one bounded task and inspect what actually happened.

Your tangible win: one crew task you can inspect.

  1. Open the preflight checkpoint. Confirm working SSH, recovery access and the account you will use.
  2. Follow the reviewed tool installation and workspace configuration. Stop at a failed check; do not install as root to get past it.
  3. Create the throwaway local Git repository. Ask the coordinator to delegate one tiny edit and test it. Use no production repository or secrets.
  4. Inspect the crew tab, changed files and test output. A coordinator saying “done” is not evidence by itself.
  5. Detach and reconnect. Identify the existing workspace rather than creating another coordinator.
Three different success claims

Installed: versions and protocol checks pass. Working: a crew completes the scratch task and its test passes. Reconnectable: you return to the same workspace after detaching. None proves production readiness or reboot recovery.

Hide the explanation. Retrieve the roles.

1. Which component keeps your crew tabs available after detaching?

Answer key and reasoning

The Herdr workspace. Detach preserves a running workspace; reboot recovery is a different problem.

2. Your agents have separate worktrees. What still matters for security?

Answer key and reasoning

The account permissions. Worktrees and local-only instructions are not a sandbox.

3. What best supports the claim that the scratch task worked?

Answer key and reasoning

Reviewed diff, passing test. Also verify a real crew tab was used before claiming delegation works.
