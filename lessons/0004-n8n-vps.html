Make one workflow reliable.

n8n connects a trigger to actions. Your VPS keeps the engine running. Those are two different jobs.

Lesson 4 · 8 minutes · optional setup: allow 60–120 minutes plus recovery practice

Learn first. You run the setup.

This page makes no server changes. Use dummy data only. We have not verified your VPS resources, Docker installation, domain, backups or prior lessons. Neither Hermes nor Pi is required.

Recall the layers

Before opening Lesson 1: why is a Docker volume not a backup? Which SSH key stays on Windows? If unsure, ask your teaching agent before executing commands.

Choose an install method, not a shortcut

Your primary reading is n8n: Install options. These are alternatives, not steps you must all perform.

What each option changes
OptionUse and trade-off
One-line setupFast bootstrap; review what it installs and exposes before executing it.
DockerRuns an image. A long run command becomes awkward to reproduce and review.
Docker ComposeRecords services, networks and volumes in a file. Our choice for a reviewable VPS lab.
npmRuns on a Node.js installation you also maintain; process supervision remains your job.
Cloud providerA hosting recipe, not n8n Cloud. You still operate a self-hosted installation.

Important source change: the current Compose guide bundles an AI Assistant sandbox, including privileged Docker-in-Docker, with a 4 GB / 2 vCPU prerequisite for that full stack. We do not copy it wholesale. Our smaller teaching adaptation uses n8n + Caddy, SQLite and no AI sandbox, Code nodes or community nodes. It is a learning lab, not a production reference architecture.

n8n recommends experienced operators for self-hosting. If you need dependable automation before you can maintain the host, consider n8n Cloud instead. Security responsibilities

Trace the request and the state

  1. DNSYour subdomain points to the VPS.
  2. Caddy · 443HTTPS terminates at the proxy.
  3. n8n · 5678Private Compose network; no host port.
  4. Persistent dataSQLite and settings live in a volume.

A reverse proxy receives a public request and forwards it internally. n8n needs the public webhook address, not its internal container address. For the reviewed modern versions we set N8N_WEBHOOK_URL=https://your-host/ and N8N_PROXY_HOPS=1. The older WEBHOOK_URL name is deprecated from 2.35.0. Adding Cloudflare or another proxy changes this topology; stop and review the trusted hops and forwarded headers. n8n reverse-proxy configuration

The data volume preserves workflows and execution history across container replacement. Credentials are encrypted using an instance key. Losing that key can make the saved credentials unusable. Back up the database, the key and configuration together, independently of the VPS. Encryption-key behavior

Your win: one harmless execution

  1. Follow the playbook checkpoints until HTTPS and the owner account are verified. Stop at any failed check.
  2. Create a workflow named Lesson 4 — dummy status. Add Manual Trigger, then Edit Fields (Set).
  3. In Edit Fields, use manual mapping to add two String fields: service = practice and status = ok. Connect the nodes.
  4. Execute the workflow. Inspect the final node’s output: one item with the two expected fields. Save the workflow. No email, API key, paid service or production system is involved.
  5. Close and reopen it. Describe the trigger, the transformation and the observed result from memory.

Primary node references: Manual Trigger and Edit Fields. A green execution proves this run—not restart persistence, external reachability or recovery.

Manual, scheduled, webhook

Manual Trigger
You click Execute. Best first test because nothing starts unexpectedly.
Schedule Trigger
Time starts the workflow. Check the workflow/instance timezone, then publish it for automatic runs. A browser tab does not have to remain open. Schedule behavior
Webhook
An HTTP request starts it. The test URL listens during a test; the production URL is registered when you publish. Inspect production results in Executions. Webhook behavior
Editor login does not protect every webhook.

Configure authentication on the Webhook node itself. Test that a request without credentials fails. Before any real side effect, validate input and decide how to reject duplicates: retrying an event must not send two invoices or delete data twice. Keep the first exercise manual and side-effect-free.

Close the explanation. Check your model.

1. Which public entry point does this lab intend?

Answer key and reasoning

Caddy on 443. Port 80 is also used for certificate issuance and HTTPS redirects; n8n has no published host port.

2. Which pair is essential to recover encrypted credentials?

Answer key and reasoning

Database and key. Recover the matching configuration too, and rehearse on separate storage.

3. What registers a webhook’s production URL?

Answer key and reasoning

Publish the workflow. Confirm the displayed production URL and inspect its actual execution.
