Trace one request.

Your first win: explain how a browser reaches an application on your VPS—and identify which layer to inspect when it fails.

Lesson 1 · about 8 minutes · concepts only · no commands to execute

A VPS is a rented computer, not just a website.

A virtual private server gives you a virtual machine with CPU, memory, storage and networking. A Linux operating system runs inside it. Your processes—and optionally Docker containers—run on that OS. You manage what you install and expose; the provider manages the underlying hosting infrastructure.

Hostinger’s dashboard is a management surface for that server. Your application is a separate running workload. You can reach one while the other is broken. Start with Hostinger’s VPS guides; see the OS reference for templates and reinstall risks.

The path to a small web application

This is an illustrative target design—not a description of your current server. A reverse proxy is one common approach, not a VPS requirement.

  1. DNS lookupFind the server address for a name.
  2. Network + TLSReach an allowed HTTPS listener.
  3. Reverse proxyRoute this hostname to the application.
  4. ApplicationRun code, query data, send a response.

The browser first uses DNS to resolve a name such as app.example.com. It then connects to an address; DNS does not carry the page. Firewall rules decide whether traffic may reach the listener. TLS establishes an encrypted connection and lets the browser verify the hostname. A reverse proxy can terminate TLS and forward requests to a private application port.

The application might run in a container. If it needs durable data, a volume can hold that data outside the container’s writable layer. The host OS underpins all these processes. Docker’s container explanation and Hostinger’s DNS guide ground these layers.

Two other paths are different.

SSH: you → SSH service → server shell, for administering the OS.
Provider API: your automation → Hostinger → provider-managed resources. It is not your application’s API.

Keep the boundaries straight

OS versus container
The OS manages the machine. A container isolates an application process but shares the host kernel; it is not another complete virtual machine. Source
Docker versus Docker Manager
Docker runs containers. Hostinger’s Docker Manager is a UI for deploying and managing Compose projects. A friendly UI does not remove the need to review ports, volumes or secrets. Source
Persistence versus backup
A volume can survive a container being removed. A backup is a recoverable separate copy. One disk failing can still lose both a container and its local volumes. Source
The surprising security trap

Docker-published ports can bypass ufw rules. Do not assume a database is private because ufw denies it. Review Docker bindings and the provider firewall, then test exposure from outside the VPS. Docker’s warning

Close the explanation. Try recalling it.

Choose an answer before checking. The aim is to explain why, not just recognize a phrase.

1. DNS resolves correctly, but the browser connection times out. What should you inspect next?

Answer key and reasoning

The firewall and listener. DNS resolution alone cannot prove a network connection is allowed or a service is listening. A timeout can have other causes too; this is the next layer to investigate, not a guaranteed diagnosis.

2. Your database uses a Docker volume. The VPS disk is lost. Which plan can recover the data?

Answer key and reasoning

Restore an independent backup. Starting a container or creating an empty volume does not reconstruct lost database records. A restore test is how you find out whether the backup is usable.

3. Automation needs to inspect provider-managed VPS resources. Which interface belongs to that task?

Answer key and reasoning

The Hostinger management API. Its token authorizes actions on your real account. An application API exposes your application's behavior instead. Primary source

Your tangible win

Without looking above, explain this in your own words: “A user opens my domain. What resolves the address, what accepts the connection, what runs the code, and where does the data survive?”

Then add: “If I lose the whole VPS, what can I restore?” If your answer stops at “a volume,” revisit the backup boundary.
